# 科研智能体平台产品宪章

版本：0.1  
状态：执行基线草案  
产品主张：**猫陪你开始，科研图帮你交付。**

## 1. 产品定义

本产品是一个基于 DeepSeek Harness 的桌面科研智能体平台。它保留 Harness 原生对话、模型、工具、工作区和插件能力，在此基础上增加科研任务入口、科研绘图交付流程和不打扰工作的猫咪陪伴体验。

它不是一个把现有网站装进 Electron 的壳，也不是对 Harness 前端核心的长期分叉。产品通过 DSH 官方 host/client 插件、runtime 和 slots 接入。

## 2. 目标用户

- 需要把研究想法快速整理为图示的研究生、博士后和青年研究者。
- 需要反复修改论文插图、汇报图或方法流程图的科研人员。
- 想使用智能体完成资料整理、任务推进和科研交付，但不愿学习复杂工程工具的人。
- 长时间独立工作，希望获得轻量陪伴和节奏提醒的用户。

## 3. 用户核心任务

1. 快速开始今天的科研工作，不先配置一大堆系统。
2. 把论文段落、研究想法、草图或要求转成结构化 FigureBrief。
3. 在生成前看清交付内容与消耗，在生成后保留版本并继续修改。
4. 导出可用于论文或汇报的 PNG；后续支持可编辑 PPTX。
5. 在不遮挡、不打断的前提下获得猫咪陪伴。

## 4. 信息架构

正式入口只保留三个：

### 今日

- 展示今日科研意图、最近工作和一个明确的“继续工作”动作。
- 提供进入 Harness 原生会话或科研绘图的快捷入口。
- 不堆叠社区信息流、商店、排行榜或运维面板。

### 科研绘图

- 新建与管理 FigureProject。
- 输入科研材料并生成/编辑 FigureBrief。
- 展示报价确认、生成状态、结果版本、修改记录与导出动作。
- 首期使用 mock 生成和 mock 计费，状态与错误流程必须真实可操作。

### 猫窝

- 管理猫咪陪伴、声音、动画强度和减少动态效果。
- 展示猫咪自己的休息空间，而不是重复粘贴其他页面上的同一张图。
- 后续可承载专注计时、轻提醒和陪伴状态统计，但不能抢占科研主流程。

社区、论文库、通用 Skills、项目/任务/运维等旧模块默认隐藏，不删除；只能通过明确的实验开关恢复。

## 5. 科研绘图最小闭环

状态顺序：

`草稿 → Brief 已确认 → 报价待确认 → 已排队 → 生成中 → 已交付`

异常状态：

`取消 / 生成失败 / 网络中断 / 插件不可用`

最小闭环必须支持：

1. 录入标题、研究背景、核心机制、关键元素、期望版式、风格和输出规格。
2. 预览并人工编辑 FigureBrief，未经确认不得生成。
3. 展示本次预计消耗；首期只做 mock 确认，不触发真实支付。
4. 生成中可离开页面，返回后仍可恢复任务状态。
5. 结果保存为不可变版本；修改产生新版本，不覆盖旧版本。
6. 下载 PNG、发起继续修改；PPTX 在能力开放前明确标为未开放或 mock。
7. 失败时提供可理解原因、重试与返回编辑，不出现永久 Loading。

## 6. Harness 集成原则

- 原生会话是平台底座，科研入口不能破坏对话、工具调用、模型选择或设置。
- 通过 DSH 插件注册侧栏入口、工作台入口、会话内科研卡片或安全的浮层。
- 不直接注册并替换整个 `conversation` 插槽，除非已有完整兼容迁移与回归证明。
- 插件 browser half 失败必须可降级；不得让 Harness 卡在 `Loading plugins...`。
- 桌面壳负责启动、端口、日志、更新和生命周期，不把业务状态写死在 Electron 主进程。

## 7. 猫咪陪伴原则

- 默认安静陪伴，不能遮挡输入框、菜单、设置、科研画布或确认按钮。
- 状态包括休息、观察、伸懒腰、玩毛线与被抚摸；随机行为应低频、可暂停。
- 点击抚摸时给出闭眼/呼噜或短猫叫反馈；声音默认克制并可关闭。
- 支持系统“减少动态效果”，键盘操作与屏幕阅读器不得被装饰层干扰。
- 页面尺寸变化、弹窗打开和下拉菜单展开时，猫咪必须主动避让或隐藏。

## 8. 非目标

- 首期不做完整科研社交网络。
- 首期不做论文管理器或通用知识库替代品。
- 首期不接真实支付、真实生产模型计费或公开多人协作。
- 不复制 AcceptCat 的全部旧页面，不把所有历史功能同时恢复。
- 不修改 DeepSeek Harness 上游核心源代码。

## 9. 质量底线

- Windows 首次启动、退出、重复启动和端口冲突都有明确行为。
- 插件加载失败可观察、可恢复，不能导致无限加载。
- 关键状态刷新后可恢复；失败不会扣费或产生幽灵版本。
- 没有密钥进入前端、日志、安装包或 Git 历史。
- 桌面常用尺寸和窄窗口均无关键遮挡、裁切和横向溢出。
- 每个已修缺陷必须有回归验证；高风险缺陷优先有自动化测试。

## 10. 阶段路线

- S0：范围与领域契约。已有参考实现，先审计后迁移。
- S1：三入口壳、路由与实验开关。
- S2：FigureBrief、报价与 mock 生成状态机。
- S3：版本、下载、修改与任务恢复。
- S4：真实 research-figure / gpt-image-2 接入与计费安全。
- S5：PPTX、更新、安装包、监控与发布门禁。

任何阶段都必须做到：类型检查、契约/单元测试、启动验证、桌面与窄屏 UI 验证、失败降级记录。

## 11. 首期成功标准

- 新用户在 3 分钟内创建首个 FigureBrief。
- 用户无需理解 DSH 插件机制即可完成 mock 科研图闭环。
- 插件异常不会阻止 Harness 原生会话启动。
- 关键页面不存在猫咪遮挡操作控件的问题。
- 一个失败任务可以被恢复、重试或安全取消。

## 12. 产品判断优先级

当文档、历史实现或个人偏好冲突时，依次服从：

1. 用户数据与系统安全。
2. Harness 原生能力可用性。
3. 科研绘图交付闭环。
4. 清晰、低摩擦的科研体验。
5. 猫咪陪伴与品牌表达。
6. 实验性或历史功能。
