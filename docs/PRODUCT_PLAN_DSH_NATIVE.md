# DSH 原生科研智能体平台产品方案

版本：1.0  
状态：**当前唯一产品执行基线**  
更新日期：2026-08-15

## 0. 方向重置声明

本项目从本版本开始重新定义，不再迁移 AcceptCat 原有业务流程、页面结构、数据模型或“科研绘图优先”的产品逻辑。

我们要做的不是“把原产品接进 DSH”，而是：

> **以 DeepSeek Harness 为运行内核，从零设计一个拥有猫猫陪伴、论文工作区和 DSH 插件市场的科研智能体桌面平台。**

AcceptCat 只允许作为猫咪素材、视觉风格和历史需求参考，不作为新平台的工程底座或业务模型来源。

## 1. 产品定位

DeepSeek Harness 已经提供会话、智能体、模型、工具、工作区、插件加载和设置能力。本产品不重复制造另一套聊天系统或插件运行时，而是在 DSH 原生能力上补齐科研用户最需要的三块体验：

1. **猫猫**：长期、安静、可交互的桌面陪伴。
2. **论文**：以本地论文为中心，把阅读、提问、笔记和科研智能体连接起来。
3. **插件市场**：发现、安装、更新和管理适配 DSH 的科研插件。

一句话定位：

> **一个有猫陪伴、能读论文、能力可以随时扩展的 DSH 科研工作台。**

## 2. 产品不是哪些东西

- 不是 AcceptCat 旧站点的桌面封装。
- 不是 DeepSeek Harness 的长期前端分叉。
- 不是另一套独立账号、聊天、模型或插件系统。
- 首期不是科研社区、论文下载站、文献数据库或付费插件商城。
- 首期不迁移旧系统的社区、钱包、积分、商店、运维、通用 Skills 页面和科研绘图状态机。

## 3. 目标用户

- 每天需要阅读、整理和讨论论文的研究生、博士后与科研人员。
- 已使用 DSH 完成编码、写作、数据分析，希望增加科研工作流的人。
- 希望按需安装文献、写作、数据、绘图等智能体插件，而不是一次安装庞大套件的人。
- 长时间独立工作，希望桌面上有低打扰陪伴感的人。

## 4. DSH 原生产品原则

### 4.1 DSH 是内核

- DSH 原生会话、工作区、模型选择、权限、工具调用和设置保持原样可用。
- 新功能通过标准 host/client 插件、`@deepseek-ai/dsh-client-runtime` 和官方 slots 接入。
- 不复制 DSH 状态管理，不在插件里维护第二套会话真相。

### 4.2 扩展而不是覆盖

- 优先使用 `sidebar.footer.action`、设置扩展位、会话输入扩展位和 `shell.overlay` 等可扩展区域。
- `sidebar`、`conversation`、`details` 等 single slot 默认已有核心占用者，不允许为了做“独立页面”直接替换。
- 需要完整工作台时，优先使用 DSH 官方页面/路由扩展；当前版本没有正式页面扩展位时，可使用可关闭、可恢复原会话的全尺寸 workspace overlay，不能销毁会话组件。

### 4.3 插件失败不能拖死 DSH

- 猫猫、论文或市场任一模块加载失败，Harness 仍必须进入原生界面。
- 每个 browser 插件都有错误边界、卸载清理和超时。
- 不允许出现因为本平台插件异常而永久停在 `Loading plugins...` 的情况。

## 5. 总体信息架构

保留 DSH 原有侧栏中的新会话、工作区、历史会话和设置，在其上增加三个科研入口：

### 猫猫

- 猫咪本体作为全局陪伴层存在。
- “猫猫中心”用于选择猫咪、状态、声音、动画和避让规则。
- 设置页提供总开关、音效、动画强度和减少动态效果。

### 论文

- “论文库”是主要科研工作台。
- 用户从本地添加 PDF，查看元数据、阅读状态、标签、笔记和相关 DSH 会话。
- 从论文打开原生 DSH 会话并携带受控论文上下文。

### 插件市场

- 浏览适配当前 DSH 版本的插件。
- 查看插件能力、权限、依赖、来源、兼容性和版本。
- 安装、启用、停用、升级、卸载以及本地开发链接。

三个入口不替代 DSH 的原生“会话/工作区”，而是帮助科研用户组织上下文和扩展能力。

## 6. 模块一：猫猫

### 6.1 体验目标

猫咪应该像在用户身边陪伴工作，而不是贴在界面上的广告或重复装饰。

### 6.2 首期功能

- 空闲时睡觉、观察、舔毛；低频触发伸懒腰或玩毛线球。
- 点击或短距离抚摸后闭眼、呼噜或播放一声克制的猫叫。
- DSH 正在运行工具、等待模型或完成任务时，可表现不同但轻微的状态。
- 猫咪只感知抽象运行状态，不读取或上传用户的会话正文。
- 可拖动到安全边缘，位置按窗口尺寸独立记忆。
- 支持隐藏 30 分钟、仅在空闲时显示、完全关闭。
- 音效默认克制、可静音；遵循系统“减少动态效果”。

### 6.3 遮挡规则

- 装饰层默认不拦截指针，只有猫咪身体的明确热区可交互。
- 输入框、模型菜单、命令面板、设置、弹窗、论文阅读器和市场确认框拥有最高交互优先级。
- 检测到菜单或弹窗展开时，猫咪自动避让、缩小或暂时隐藏。
- 窄窗口下只允许出现在不覆盖主操作的停靠区域。

### 6.4 猫猫中心

- 当前猫咪与外观。
- 陪伴行为频率。
- 音量和声音开关。
- 动画强度、减少动态效果。
- 位置重置与“暂时休息”。

首期不做猫粮货币、抽卡、复杂养成和付费皮肤。

## 7. 模块二：论文工作区

### 7.1 核心目标

论文模块负责管理“论文对象和它的科研上下文”，具体分析、写作和工具调用继续由 DSH 原生会话与插件完成。

### 7.2 论文库

- 从本地选择 PDF；首期不提供盗版下载或绕过站点权限的抓取。
- 读取标题、作者、年份、DOI 等元数据，无法识别时允许手工编辑。
- 列表支持最近阅读、未读、收藏、标签和搜索。
- 记录本地文件位置、阅读进度、笔记与关联会话。
- 文件移动或丢失时显示修复路径，不删除已有笔记。

### 7.3 论文阅读器

- PDF 页面、目录、缩放、页码和全文搜索。
- 文本选择后可以“询问 DSH”“解释”“翻译”“加入笔记”。
- 笔记保留论文页码和引用来源。
- 阅读器与 DSH 会话可并行切换，不创建第二套聊天界面。

### 7.4 论文与 DSH 会话

- “在 DSH 中讨论”创建或打开关联会话。
- 只传递用户选择的片段、页码或明确授权的全文索引，不默认把整篇论文塞进上下文。
- 会话卡片显示论文来源和页码，可返回阅读器定位。
- 插件可以声明自己支持的论文动作，例如总结、审稿、公式解释、数据提取、科研绘图或引用整理。

### 7.5 数据原则

- 论文、索引、笔记和阅读进度默认本地保存。
- 明确显示哪些内容会发送给模型。
- 删除论文记录时区分“仅从库移除”和“同时删除本地文件”。
- 不把论文内容写入普通日志、崩溃报告或插件市场遥测。

## 8. 模块三：DSH 插件市场

### 8.1 定位

市场是 DSH 插件的发现与管理界面，不创建另一套插件格式。安装行为最终必须落到当前 DSH profile 的官方插件管理机制。

### 8.2 市场首页

- 分类：论文阅读、科研写作、数据分析、科研绘图、引用管理、效率工具、猫猫扩展。
- 搜索、兼容版本筛选、已安装筛选。
- 推荐位只展示经过审核且兼容当前 DSH 版本的插件。

### 8.3 插件详情

- 名称、作者、版本、更新时间、许可证和源代码地址。
- 功能说明、截图、变更日志和支持的 DSH 版本。
- 所需权限、网络访问、文件访问、依赖和安装脚本。
- 安装前给出明确影响说明，不把权限藏在长文本里。

### 8.4 插件管理

- 安装、启用、停用、升级、卸载。
- 显示安装进度、失败原因和恢复动作。
- 支持开发者以 `link:` 方式加载本地插件，并明确标记“开发模式”。
- 卸载不能删除插件之外的用户论文和会话数据。
- 插件升级失败时保留上一可用版本或提供明确回滚路径。

### 8.5 安全与供应链

- 市场索引必须有来源、版本和完整性校验。
- 显示依赖脚本；需要运行构建脚本时单独授权。
- 区分官方、已验证社区和未验证来源。
- 不静默批准 `pnpm approve-builds`，不绕过 DSH lockfile 和供应链策略。
- 插件发生运行时异常时允许单独禁用，不拖垮整个平台。

首期不做插件付费、分成、评论社区和作者结算。

## 9. 三模块联动

### 从论文到智能体

1. 用户在论文库打开 PDF。
2. 选择段落并点击“在 DSH 中讨论”。
3. 系统创建带来源卡片的原生 DSH 会话。
4. 如果缺少所需能力，提示用户到插件市场查看兼容插件。
5. 安装后回到原会话继续，不丢失论文定位和上下文。

### 猫猫与科研工作

1. 用户阅读或运行智能体时，猫咪安静休息。
2. 长时间无交互时猫咪低频活动，但不弹出强提醒。
3. 任务完成后猫咪给出短暂庆祝反馈。
4. 设置、安装确认或论文选择菜单出现时猫咪主动避让。

## 10. 技术模块建议

新仓库建议按 DSH 插件边界组织，而不是按旧网站页面复制：

```text
apps/
  desktop/                  # Electron 壳、单实例、日志、更新
packages/
  dsh-research-hub/         # host/browser 聚合入口与导航
  dsh-cat-companion/        # 猫咪状态、资产、设置、陪伴层
  dsh-paper-workspace/      # 论文库、阅读器、会话上下文桥接
  dsh-plugin-market/        # 市场目录、安装与插件管理 UI
  research-contracts/       # 跨插件的稳定类型和事件契约
docs/
```

各模块必须可以单独禁用和安全降级。`dsh-research-hub` 只负责协调入口，不成为所有业务逻辑的巨型包。

## 11. 领域边界

### 猫猫

- `CatProfile`
- `CatBehaviorState`
- `CompanionPreferences`
- `SafeDockRegion`

### 论文

- `PaperRecord`
- `PaperSource`
- `PaperNote`
- `ReadingProgress`
- `PaperSessionLink`
- `SelectedPaperContext`

### 插件市场

- `MarketplaceEntry`
- `PluginManifestView`
- `PermissionDisclosure`
- `CompatibilityResult`
- `PluginInstallJob`

这些模型不能直接复用 AcceptCat 的旧接口；需要根据 DSH runtime、profile 和插件 manifest 重新设计。

## 12. 实施阶段

### P0：DSH 原生骨架

- 建立独立 monorepo、桌面壳和三个可单独启停的插件包。
- 验证官方 host/client 加载、侧栏入口、设置扩展、工作台容器和失败降级。
- 建立启动、端口、日志和插件故障回归测试。

### P1：猫猫 MVP

- 一只猫、三种空闲行为、抚摸反馈、静音和减少动态效果。
- 完成输入框、模型菜单、设置和窄窗口避让测试。

### P2：论文 MVP

- 本地 PDF 添加、论文库、基础阅读器、笔记和阅读进度。
- 选中文本后创建带来源的 DSH 会话。

### P3：插件市场 MVP

- 使用 mock/本地签名目录完成浏览、详情、兼容性和权限披露。
- 调用受控 DSH 插件管理适配层完成安装、停用和卸载。

### P4：三模块联动

- 论文动作与已安装插件能力发现。
- 会话来源卡片、返回论文定位、缺失插件推荐。
- 猫咪根据抽象运行状态反馈。

### P5：桌面发布

- Windows 安装包、单实例、端口冲突处理、日志诊断。
- 自动更新、失败回滚、插件兼容门禁和发布验收。

## 13. MVP 验收标准

- 不安装额外插件时，DSH 原生会话仍能正常启动和工作。
- 猫咪可交互、可关闭，且不会遮挡任何关键操作。
- 用户能添加一篇本地 PDF、阅读、记录笔记，并把选中内容带入原生 DSH 会话。
- 用户能在市场查看插件权限与兼容性，并完成一次安全的 mock 或本地插件安装流程。
- 三个模块任一发生异常时，另外两个模块和 DSH 原生能力不被阻断。
- Windows 重复启动、端口占用和插件加载失败都有可操作提示，不出现永久 Loading。

## 14. 当前决策与待决策

已确定：

- 三个核心模块为猫猫、论文、插件市场。
- DSH 是产品内核，所有能力按 DSH 插件方式适配。
- 不迁移旧产品逻辑，不先做科研绘图闭环。
- 原参考目录保持只读，新仓库独立实现。

后续视觉实现前仍需确认：

- 三个入口在 DSH 侧栏中的具体顺序和呈现方式。
- 论文工作台使用官方页面扩展还是可恢复的全尺寸 workspace overlay。
- 首发猫咪形象与猫窝场景。
- 插件市场索引的首个可信来源与签名策略。
